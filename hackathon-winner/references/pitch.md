# Pitch, Demo and Judge Q&A

Judges see 30–100 demos in a day, often in a few minutes each, and many of them are not deeply technical. They cannot reward what they did not understand.

## 3-minute pitch template

| Time | Beat | What to say / show |
|---|---|---|
| 0:00–0:30 | **Person + pain** | A specific person in a specific moment. Make it hurt a little. Use a real number if you have one. |
| 0:30–0:45 | **One-line solution** | "[Product] lets [person] [do the thing] without [the pain]." |
| 0:45–2:15 | **Live demo** | Walk the happy path as that person. Show the "aha" moment clearly. No tour of settings pages. |
| 2:15–2:40 | **Impact** | Who benefits, how much time or money it saves, what changes. Quantify where possible. |
| 2:40–2:55 | **Built with** | Name each sponsor tool and what it did in the demo — one line each. |
| 2:55–3:00 | **Close** | Restate the one-liner. Stop on time. |

Shorter slot? Keep the ratio: about 15% problem, 10% solution, 50% demo, 15% impact, 10% close.

## Prepare three lengths

- **10 seconds** — for people walking past your table
- **60 seconds** — for sponsors and mentors mid-event
- **Full slot** — for the stage

## Demo rules

- Seed realistic demo data. Never type passwords or wait on slow sign-ups live.
- Have the backup video queued in another tab. If anything stalls for more than ~5 seconds, switch to it calmly.
- Demo on the target platform (a phone for a mobile track, a live URL for web).
- Zoom the screen so the back row can read it.
- One person drives, one person talks.

## Q&A drill

Before judging, the team quizzes each other as if they had not seen each other's work. Decide in advance who answers which type of question.

Questions to have answers ready for:

1. Why this tech stack and not another?
2. What is real and what is mocked or hard-coded?
3. How does it scale / what breaks first?
4. Who would pay for this, and who actually uses it?
5. How did you use [sponsor]'s product, and why was it the right fit?
6. What would you build next?
7. What already exists, and why is this different?

**Missing features:** describe them as deliberate scope choices and roadmap items, not as running out of time. Be honest about what is mocked if asked directly.

## Submission assets checklist

- [ ] Demo video (under the length limit; problem in the first 15 seconds)
- [ ] README that explains the problem, the solution, how to run it, and which sponsor tools were used
- [ ] Clean commit history and a license in the public repo
- [ ] Screenshots or GIF at the top of the README / submission page
- [ ] Every sponsor track entered on the submission form
- [ ] Submitted before the deadline, with time to spare
